# Media Prompts — Operation Zero
## Detective Files — Mission 20

Version: 1.0

**Status note:** as explained in `media-assets.md`, no asset below is
currently required for Mission 20 to be playable — the applications that
would display them don't render image/video fields yet. These prompts
exist so generation can begin whenever that changes, without needing to
redesign the case's visual scope at that time. Per Part 9 ("do not
overproduce"), several prompt categories below intentionally contain no
entries, with the reasoning stated instead of a padded asset.

Every prompt in this document must be read together with this fixed
instruction, which is not repeated per-row to keep the table legible but
applies to **every single prompt on this page**:

> Use the previously established Detective Files art style, character
> designs, environment design, and visual identity. Do not redesign
> existing characters. Do not change character appearance between
> scenes.

The established visual identity, per `docs/UI_GUIDELINES.md`: low-detail
pixel art, retro desktop OS, police workstation aesthetic, dark theme,
professional, minimal, functional. **No dedicated Character Bible
document exists in the project yet** — this is called out as an
assumption in the implementation summary. Until one exists, prompts below
describe each character's appearance in enough detail to stay consistent
across their own scenes, but a future character bible should supersede
these descriptions as the single source of truth.

## 8. Investigation Board Content

No dedicated board imagery is recommended for Mission 20. The
Investigation Board renders evidence, person, and theory cards from
existing text/emoji data (`apps/board/index.js`) rather than pinned
photographs — generating board-specific art would duplicate the
Evidence/Character assets above without adding gameplay value, which
Part 9 explicitly asks us to avoid.

## 12. Tutorial Visual Hints

No image assets are recommended for tutorial visual hints. Mission 20's
"subtle guidance" and "tooltip" requirements are already satisfied by
`TooltipManager` (a small text bubble anchored to the relevant desktop
icon or taskbar button) and by existing priority-based highlighting —
both are CSS/DOM effects, not generated imagery. Adding illustrated hint
graphics on top of these would be exactly the kind of unnecessary
production Part 9 warns against.

## 13. Required Video Scenes

**TF20-VIDEO-001 — Back Alley Camera footage**

| Field | Value |
|---|---|
| Video ID | `TF20-VIDEO-001` |
| Scene description | Danny Cole exits the pawn shop's back door; moments later a man (Marcus Reed) approaches from the alley; the two move out of frame together. |
| Characters | Danny Cole, Marcus Reed (silhouetted/obscured is acceptable given the in-fiction unidentified status at first viewing) |
| Location | Back alley behind Third & Main Pawn & Loan (`loc-000-1`) |
| Action | Danny exits → pauses → Reed enters frame → brief exchange → both exit frame together |
| Camera direction | Fixed, static security-camera angle, slightly elevated, matching `camera-000-1`'s established position |
| Lighting | Low, single alley light source, grainy/low-contrast, consistent with the CCTV frame stills above |
| Duration recommendation | 10–12 seconds (matches `camera-000-1.duration` window around its `importantTimestamps`, well within the 5–15s guidance) |
| Transition | Hard cut in / hard cut out — CCTV footage should not use stylized transitions |
| Google Flow video prompt | Use the previously established Detective Files art style, character designs, environment design and visual identity. Grainy, low-resolution retro CCTV footage, static elevated camera angle, black-and-white, showing a young man exiting a back door into a narrow alley, pausing, then a second man approaching from off-frame; the two exchange a few words and walk off together out of frame. No dialogue audio, ambient street noise only. Timestamp overlay in the corner. Do not redesign existing characters. |

This is the **only** video proposed for Mission 20. Per Part 9, it is
also the only one that meaningfully needs to be a video rather than a
still frame — the two CCTV Frames in Section 7 already convey the same
beats as static images, and `camera-000-1.importantTimestamps` conveys
the same information as text. Generation of `TF20-VIDEO-001` should be
treated as a "nice to have" that can be deferred indefinitely (see
`media-assets.md` — Required: No) rather than a blocker for anything.
